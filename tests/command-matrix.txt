# git-guard command matrix

# Every line below was run through .claude/hooks/git-guard.py and the verdict
# recorded is what the hook ACTUALLY returned, not what it ought to return.
# Where the two differ the line is tagged; see "Known gaps" and "False
# positives" at the bottom.
#
# Format:  <VERDICT>  <tab>  <command>            [# note]
#   DENIED   hook returns permissionDecision=deny, command never runs
#   ALLOWED  hook stays silent, command runs
#
# Config at time of capture: .claude/settings.json has NO "if" filter, so the
# hook is spawned for every Bash call. Re-adding an "if" rule changes many of
# the ALLOWED/DENIED results in the "command prefixes" section below.
#
# Regenerate after changing READ_ONLY or OPTS_WITH_VALUE — the verdicts are a
# snapshot, not a specification. Every row is replayed through the hook by
# `pytest tests/test_git_guard.py -k matrix`, one test per row.

## 11. Known gaps — currently ALLOWED, arguably should be DENIED
# All four were executed against the live hook and did run. They are the
# regression targets if you decide to harden the parser.
#
# 11.1  Backtick substitution. `$(...)` is caught because shlex splits on the
#       punctuation, but a backtick binds into the token: "`git" != "git".
#         `git push`
#         echo `git config --get user.email`
#
# 11.2  Any git call inside a quoted string passed to another interpreter.
#       shlex yields "git commit -m x" as ONE token, so it never equals "git".
#         bash -c 'git commit -m x'
#         sh -c "git push"
#         eval 'git commit -m x'
#
# 11.3  Case. The check is case-sensitive, but macOS filesystems are not, so
#       PATH lookup resolves GIT -> the git binary and the command runs.
#       Not a gap on a case-sensitive filesystem (Linux, or macOS APFS-CS).
#         GIT config --get user.email
#
# 11.4  Indirection — the literal token "git" never appears at all. Inherent
#       to any string-matching hook; listed so it is not mistaken for a bug.
#         G=git; $G commit -m x
#         alias g=git; g push
#         bash scripts/deploy.sh          (script contains git commands)
#
# 11.5  Allowlisted subcommands that execute arbitrary programs. difftool is
#       in READ_ONLY but -x takes a command to run.
#         git difftool -x 'sh -c whoami'


## 12. False positives — currently DENIED, harmless but noisy
#
# 12.1  "git" as a bare argument to another program. The parser sees the token
#       "git" and reads the next token as its subcommand.
#         echo git commit
#       Quoting avoids it: echo 'git commit' is ALLOWED.
#
# 12.2  Subcommand case. git itself rejects "git COMMIT", so denying it costs
#       nothing, but the reason string reads oddly.
#         git COMMIT -m x
